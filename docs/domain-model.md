# Доменная модель

## Границы агрегатов

Сейчас вся модель проекта — один «мега-агрегат» `Project`. Каждая область лежит в своём partial-файле
`Project.*.cs` и своей папке, чтобы потом её можно было вырезать в отдельный агрегат.

| Область | Файлы | Кандидат в отдельный агрегат |
|---|---|---|
| Жизненный цикл проекта | `Project.cs` | — (корень) |
| Роли | `Project.Roles.cs`, `Roles/` | нет, правила ролей зависят от команды |
| Команда и ставки | `Project.Team.cs`, `Team/` | нет |
| Финансирование | `Project.Funding.cs`, `Funding/` | нет |
| Рабочие пакеты и задачи | `Project.WorkPackages.cs`, `WorkPackages/` | да, `WorkPackage` |
| Сетевой график | `Project.Schedule.cs`, `Schedule/` | да, `ScheduleNetwork` |
| Milestones | `Project.Milestones.cs`, `Milestones/` | возможно |
| Риски | `Project.Risks.cs`, `Risks/` | да, простой CRUD |

`Employee` — отдельный агрегат: сотрудник не принадлежит одному проекту, проект ссылается на него по Id.

Пока агрегат один, проверки между областями делает сам `Project`:

- ответственный за пакет или задачу состоит в команде проекта;
- записывать время может только член команды на дату записи;
- задача, добавляемая в milestone, принадлежит проекту;
- при отмене пакета или задачи её зависимости удаляются в той же операции.

После разрезания эти проверки переедут в доменные сервисы.

## События

Агрегат только поднимает события (`AggregateRoot.DomainEvents`). Восстановление состояния из событий
(event sourcing) пока не реализовано.

## Read-сторона (вычисляется, не хранится)

Milestone:

- прогресс — сколько задач готово из учитываемых (отменённые задачи остаются в наборе, но не учитываются);
- опоздание — `TargetDate` прошла, а статус ещё Open;
- «закрыт с хвостами» — Completed, но внутри есть незавершённые задачи;
- пустой milestone не считается достигнутым.

Финансирование (по `FundingAdded`, `WorkLogged`, `TeamMemberAdded`, `HourlyRateChanged`):

- total funding = Σ `FundingTranche.Amount`;
- actual cost (AC) = Σ `Hours` × `HourlyRate`, действовавший на `TimeEntry.Date`;
- остаток = total funding − AC на любой момент времени;
- старые затраты не пересчитываются: ставку нельзя поменять задним числом.

## Открытые вопросы

- `FundingExceeded` — событие при превышении финансирования (для уведомлений) должно быть. Остаток
  вычисляемый, поэтому не решено, в момент какой операции превышение «возникает» и кто поднимает событие.

## Risk

Risk — простая запись реестра (CRUD) без инвариантов, доменного поведения и событий. Он не участвует
ни в одном правиле остального домена. По Эвансу, тактические паттерны DDD оправданы для core domain,
а вспомогательные части (supporting subdomain) могут быть простым CRUD.

Точки роста, которые сделали бы Risk частью домена:

- risk response (mitigate и т. п.) порождает tasks / work package — риск как источник изменения scope;
- contingency reserve — часть funding, обоснованная конкретными рисками;
- наступление риска (risk → issue) как событие с последствиями;
- opportunities (положительные риски).
